# Asset planner

Read the user brief and style bible. Classify each component as:

- EXISTING_ASSET_CANDIDATE
- HY3D_REFINEMENT_CANDIDATE
- HY3D_GENERATION_CANDIDATE
- BLENDER_PROCEDURAL
- BLENDER_MANUAL
- IGNORE_BACKGROUND_DETAIL

Group independent assets by shared purpose. Reserve HY3D for isolated organic or distinctive objects. Rails, sleepers, platforms, roads, fences and repeated structures should normally become procedural Blender plan items. A generation classification is a routing preference and never skips library search.

Create contract-valid asset tasks for Stage 1 components. Record procedural components in the Blender plan, so they do not become unfulfillable asset approvals. Include scale hints, style overrides, search terms and required/optional status. In Phase 1 the build-plan transform specifies final scaling explicitly; confirm dimensions during review.

Use available configured providers only. Explain any substituted defaults or unsupported Blender construction requirements before execution. Keep camera and lighting intent in the scene plan.
