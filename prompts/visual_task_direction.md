# Create a visual direction

Read the prepared task's declared brief, measured scene structure, Style priors and optional references, knowledge and observations. Use the user's approved goals to choose camera, composition, lighting, atmosphere and visual hierarchy. View relevant declared raster references. Return one `visual_task_direction` result with a null parent and the exact primary subject. Preserve all caller constraints and Style avoid rules.

Only supported camera/light controls can become executable plans. Do not change approved geometry, the layout, materials, production state or approvals. Describe conflicts rather than invent missing facts. Provide explicit execution choices for softness and fog, with the reason they implement the authored direction. Runtime validates and compiles these choices; it does not interpret qualitative prose.

Submit through the task tool, then let the main workflow validate and accept it with the scene plans. A valid candidate is not production completion.
