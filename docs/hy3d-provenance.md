# Official Hunyuan3D-2.1 output provenance

Read at SKILL.md Steps 2, 1G and 6, before Step 3 generation when using the legacy route. The operator must verify the configured backend's actual model identity and applicable terms before setting `license_verified`; a metadata match is not remote model attestation. This support records model/output provenance for local modeling validation. It does not establish universal output ownership or authorize external distribution.

The official [Community License](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/LICENSE) was checked on 2026-09-14. Section 6(d) says Tencent claims no output rights and assigns output responsibility to users. This is not CC0. Section 5(b) prohibits using outputs to improve other AI models, except Hunyuan3D-2.1 and its model derivatives. Section 5(c) excludes use of outputs in the EU, UK and South Korea. Section 4 requires additional authorization where the specified release-date monthly-active-user threshold exceeds one million. Applicable laws and the Acceptable Use Policy remain relevant. Recheck the full terms for a changed use or distribution scope.

Example `output_source`, only after the deployment and source review described above:

```json
{
  "provider": "hy3d",
  "asset_id": "tencent/Hunyuan3D-2.1",
  "original_url": "https://huggingface.co/tencent/Hunyuan3D-2.1",
  "creator": "Tencent Hunyuan3D-2.1 model; output generated by project operator",
  "license": "hunyuan3d_21_community",
  "license_verified": true,
  "attribution_required": true,
  "modification_allowed": true
}
```

The scoped policy requires these exact provider, model ID and URL, verified rights, and retained attribution. Processing that changes the asset additionally requires modification permission. Only explicit generated-output preflight and persisted generated-route validation activate it. Library candidates, supplied assets without generated-route evidence and generation references keep their existing policies. The generic CC0/CC BY allowlist is unchanged. Other Hunyuan versions and third-party hosted services require separate source review and support; this entry cannot stand in for them.

Keep the actual `source`/`provenance` object throughout geometry review, Blender processing and delivery. The supported asset delivery path writes the same object to `delivery.yaml`, `attribution.yaml` and the manifest snapshot. Preserve this guide and the applicable agreement/notice with local handoff records; `attribution_required: true` is a conservative retention choice, not a finding that every output is a distributed model derivative. A future distribution must evaluate its own agreement/notice obligations. File validation and successful inference do not approve the artwork.
