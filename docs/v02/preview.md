# Formal preview passes

`preview-prepare PROJECT` reserves a new pass through ManifestManager and returns a guarded MCP job. Execute its render_job call in Blender, usually in a timer to keep MCP responsive. Preparation and queueing produce no success claim. The semantic worker checks inputs, restores or reuses the saved geometry, applies the current visual plans and renders explicitly. It writes only a worker receipt, not official metadata or approval.

After actual completion, `preview-complete PROJECT --job JOB.json` validates the job identity, current input hashes, receipt and actual PNG signature/chunks/CRC/pixel stream/dimensions. It stores `stage2/previews/pass_NN/render_metadata.json` through ManifestManager. Metadata includes project/scene version, build_id, pass_id, style_profile, renderer, render_plan_id/hash, timestamp, render_success and the image path/hash. Successful completion enters render_review_required; it never sets visual_approved or adds an approval decision.

Each explicit prepare reserves a new directory and increments the render-plan revision, retaining prior images and metadata. A manual repeat from render_review_required passes through the existing visual_revision → render_pending edges. This is an explicit technical render request, not an automated critic or revision loop. Failed renders retain metadata with render_success false, image null and an error, leave render_pending, and do not select another backend. A queued/missing receipt or corrupt/mismatched output cannot be completed. Repeating complete on a stale job rejects.

Scene setup must already have completed. The first version supports PNG previews in Cycles/Eevee, the six registered material classes and a single body slot per object. Texture-source blending and automatic visual critique remain outside this phase. Regenerate machine-specific operation packets after moving a project; Blender reloads the saved blockout when the owned build scene is not in memory. Active user scenes are preserved.

The final focused preview suite passed 12 cases; full active regression passed all 26 groups. Validate reports no warnings; declared/runtime contracts passed. Raw evidence is in `.deps/v02-phase6/`.

Actual MCP passes 00 and 02 rendered and recorded successfully. Cold restores exposed a geometry fingerprint mismatch; failed passes 01 and 03 were recorded with render_success false and image null. Detailed evaluation showed restored world matrices initially remained identity until Blender evaluation was forced. The worker now refreshes the frame/object evaluation before hashing; signed zero is also normalized, and fingerprint format 2 creates a separate build cache without overwriting earlier evidence. Cold-restored pass 04 then rendered successfully with the saved geometry digest unchanged. Its PNG was inspected and formal metadata verified against the actual bytes. The current state is render_review_required with no final approval. Paths, hashes, pass outcomes and evidence scope are in `.deps/v02-phase6/representative.json`. Reproducibility here means stable plans, geometry and traceable execution; bit-identical PNG output across scene reloads was not established.

## Resume with visual tasks

Inspect the current [visual task](task-tracking.md) and existing render job together. Accepted direction tasks continue setup/preview, available reviews are collected before another review is authored, and running or unknown attempts are verified before retry. Preparing or completing a task never reserves a preview pass by itself. Collect the existing current receipt before considering any new render.
